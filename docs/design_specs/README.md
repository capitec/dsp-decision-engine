# Design specs

Proposals for work not yet built, one folder per rework, named `<date>_<topic>/`. A spec describes the
current code it touches, the target design, the choices and their alternatives, the trade-offs, the
experiments that decide them and an implementation plan. Not published on the docs site.

When a spec is implemented, its rationale moves into `docs/design_decisions/` (decisions and experiments)
and `docs/architecture/` describes the result; the spec folder stays as history.
