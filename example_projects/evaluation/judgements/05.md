## 2. Similarity

The two designs share little beyond the stage names.
- **Haiku** has one `flow` step wrapping a plain-Python `assess_business_credit()` (`assessment.py:444-562`) over dataclasses, with every loop hidden inside it.
- **Sonnet** is a `dag` of ten units (`pipeline.py`). Each ragged stage is a `frame_step` that wraps a pure function. The nested request is flattened into long-form `entity_*`, `ev_*` and `attr_*` arrays joined by id (`structure.py`). Per-entity `ScorecardConfig` and `DecisionTableConfig` lookups run through a second `Engine` bound at import (`scoring.py:200`, `events.py:112`).

I ran the spec's worked examples through both implementations' functions (scripts in the scratchpad). Both classify correctly:
- R80 000 unsatisfied judgment: material on a peripheral entity, disqualifying on a controlling one.
- Six R30 000 judgments: AE-R-06, material, attributed to all six events.
- Three recent minor events: AE-R-02, attributed to all three.

They diverge on the rest of the slice:

| Slice item | Haiku | Sonnet |
|---|---|---|
| Two-path de-dup (AC4) | None: the same key gives 2 verdicts | Sum, most-senior role, OR of control flags, events attached once (`structure.py:77-105`) |
| Shuffle invariance (AC3) | Fails: two disqualifying entities, shuffled, give `declined_entity_key` `b` then `a` | Sorted by id, tested ×10 |
| Overlay at position 1 | Fields copied, never altered (`assessment.py:233-237`) | `core.adjustments` applied before classification, base and used values recorded. R7 000 is material in sector 412 and minor elsewhere |
| Blend | Arithmetic mean of PDs, which the spec calls a defect. The grade is inverted: `int(12 - pd*200)` gives people_grade 1 over material entities | Log-odds blend with PP-01..05, part of PP-06, and PP-11 as an aggregate delta |
| Entity scoring | Grade taken from the adverse verdict (stub) | Real scorecard → 00 calibration → grade, with overlay and unadjusted values |
| Counterfactual and partial re-run | None | Both implemented and tested (`counterfactual.py`) |
| Sole proprietor via 02 | Stub (NOTES) | Real call into 02's `pipeline.build()` |

**Sonnet's deviations from the spec:**
- It uses 00's event-type enum, not the spec's, so spec code 14 (fraud) is treated as 00's `REGULATORY_FINDING`.
- Judgment ageing rules AE-C-01, -04 and -05 are lost because 00's classifier ignores age. It also uses `>=` where the spec says `>`.
- Disputed-sole-cause referral (AC9) is missing. With event 41 disputed, the outcome is still a decline (reason 5602, by grade).
- There is no graph traversal; the caller supplies per-path ownership.

Even so, Sonnet is much closer to the spec.

## 3. Maintainability

**Haiku** is short (562 lines) and readable. However, thresholds are a dict inside the function body, the default is `decision_date = missing_as(date.today())`, the decline attribution is order-dependent (last one wins), and request fields are params.

**Sonnet** is well factored: each module is a pure function plus a step wrapper, and the long docstrings explain *why*. The costs are verbosity, tables and overlays declared in Python rather than `configs/`, and private access (`grade_mod._BUSINESS_OVERLAYS`, 00's `_ALWAYS_DISQUALIFYING`, `_warm`). `partial_reassess_entity` also passes the adjusted verdict as the unadjusted one (`counterfactual.py:185-186`) and stops at the grade, not the outcome or offer.

Summary accuracy:
- **05-haiku.md: 4.** It is accurate about the stubs, the missing overlay and the mean blend. It says "Apply 12 rules" and misses the inverted grade mapping and the param-shadowing bug.
- **05-sonnet.md: 3.** It gets the flattening, nested Engine and date trap right, but makes several errors:
  - It calls entity verdicts "pass/refer/decline"; they are clear/minor/material/disqualifying.
  - It says the sole-proprietor check means "single person owns 100%"; the code gates on `legal_form_code == 1`.
  - It says severity uses age; it does not.
  - It says the scorecard is "per natural person"; all entities are scored.
  - It calls the product-scoped overlay a sector multiplier.
  - It omits the counterfactual, the partial re-run and the 02 call.

## 4. Reuse

- **Haiku: none.** It has no import from 00 or 02 (checked with grep). Haiku 00 has `scorecard`, `calibration`, `risk_grade` and `adjustments`, all unused. Its NOTES admit this. The only built-ins used are `flow`, `param` and `missing_as`; the loops, scoring and blend are hand-rolled.
- **Sonnet: real.** From 00 it calls `event_severity_code`, `event_age_months`, `AdjustmentRegister` (three registers), `calibration` (entity and financial), `instalment`, `fees`, `rounding`, `ReasonCodeRegistry` and `evidence.cell_id`. It also calls 02's full pipeline for sole proprietors (tested in `test_sole_proprietor.py`). It does not reuse 00's `scorecard`, `risk_grade`, `appetite` or `bureau`. It justifies the risk-grade and appetite tables as gaps (00 has no product 50/51 rows). It uses `ScorecardConfig` ×2 and `DecisionTableConfig` ×5 rather than hand-rolling them.

## 5. Struggles

**Haiku**
- Agent capability: build and params verification were not done despite the instruction, NOTES are inaccurate ("11 passed", "build succeeds", "decision_id… table versions" appear nowhere in the output), and the module-name collision with 02 went unnoticed.
- Framework friction it cites ("no loop decorator") is plausible, but it never tried `loop` or `frame_step`.

**Sonnet**
- Framework problems:
  - No construct runs per element of a nested collection, which forced the nested `Engine`.
  - Nested outputs (`list[struct]`, `list[list]`) cannot be emitted.
  - A `list[date]` silently degrades to ints between `frame_step`s. I did not independently reproduce this.
  - A warm-up monkeypatch is required, which I confirmed.
  - The typo guard gives a false positive (`entity_bureau_score` vs `entity_base_score`).
  - Same-named `pipeline.py` files force `importlib` loading by path.
- Spec problems: the 00 and 05 event enums differ, the corporate-guarantor criticality clause is out of scope, and `recent_adverse` is referenced but AE-R-08 is outside the six-rule subset.
