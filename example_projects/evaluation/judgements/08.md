## 2. Similarity

The designs differ.
- **Haiku** is one monolithic step (`assess_treatment`, `assessment.py:204`). It rebuilds a 5,376-entry Python dict on every call (`generate_sparse_matrix`, `:327`). That generator ignores balance band, contact band and product family, and it only ever emits treatments {1, 2, 4, 5, 6, 7}.
- **Sonnet** decomposes the slice into six `dag` units plus a population-level `frame_step` (`pipeline.py:81-193`).

Stage by stage:
- **Matrix.** Both generate all 5,376 cells. Haiku's `cell_id = hash(key) % 5376` gives **3,494 distinct ids for 5,376 cells**, so cell attribution is broken. Sonnet's is a `DecisionTableConfig` with `credit_core.evidence.cell_id` ids.
- **Suspensions.** Haiku checks 8 codes (`assessment.py:98-137`). It maps `external_debt_counselling` to 108 (internal complaint), and has no expiry, source or scope. Sonnet evaluates all 20 codes with no early return, each with scope, source and expiry (`suspensions.py:182-280`). Spec check: 14 Aug 2026 plus 10 business days gives 28 Aug.
- **Suspension bug (Haiku).** A suspended account records reason **200**, not 210: the 210 set at `:242` is overwritten at `:257`.
- **Suspension bug (Sonnet).** Only six codes block (`vocab.SUSPENSION_BLOCKS_ALL`). The rest never narrow `permitted_treatment_codes` (`suspensions.py:290-302`). As a result, `debt_review_stage_code=1` (101, "all collections contact except statutory notices") and `hardship_arrangement_performing` (111) still get an **allocated agent call**. I verified both through the handler. This is the §9.2 failure mode.
- **Overlays.** Haiku has none: `applied_overlay_ids=[]` and adjusted equals unadjusted (`:72`). Sonnet has four score kinds and two matrix kinds on `credit_core.AdjustmentRegister`, with authoring-time rejection of statutory targets. With `agency_placed_12m` the score goes from 640 to 618 and the band from 3 to 4, with the unadjusted value kept.
- **Overlay caveats (Sonnet).** The "band boundary shift" subtracts 0.03 from the probability, which moves *all* edges, not just 3/4 (`scoring.py:368-383`). The "unadjusted" band is computed from the already score-shifted and scale-changed value (`scoring.py:165`, which reads `collections_score`).
- **Path and temporal state.**
  - Haiku: `path_position = intensity_ceiling + 1` if any previous treatment exists. `episode_id` and `rank_in_pool` come from `hash((id, date))`, which is salted per process. Two identical runs gave `episode_id` 628019939 and 1211772812, and rank 52 and 85, which violates §8 determinism.
  - Sonnet: a reset-effect table plus the roll-carry and floor rules, run twice via `.relabel` for as-known versus as-at-now. The caller supplies both flag sets, and nothing is derived from feed watermarks. The replay test drives the plain function on crafted accounts, not ~200k accounts through decider.
  - Sonnet's path never changes `treatment_code`: `must_escalate` and `path_floored_intensity` are only evidence.
- **Arrangements.** Haiku only sets a flag. Sonnet runs 02 for real, plus its own R350/5%/85% sustainability test. The arrangement minimums grid, counts and authority levels are absent from both.
- **Capacity.** Haiku's "rank" is a hash mod 100. Sonnet ranks per pool with a stable `account_id` tiebreak, an 8% reserve for bands 6–7 and codes 200–250, except 260 and 270.

Sonnet is much closer to the spec.

## 3. Maintainability

**Haiku.** The code is short and readable, but it is misleading:
- NOTES and SERVE claim 20 codes, four overlay kinds and 28 characteristics simplified to 10.
- Thresholds are hard-coded (`assessment.py:211-222`).
- `decision_date = missing_as(date.today())` reads the wall clock at import time.

**Haiku summary: 4/5.** It accurately lists the stages, the 8 codes, the hash-based episode, and that the matrix, capacity and overlays are stubs. It did not notice three things: the inputs are params, so requests are ignored; the ids are non-deterministic; and suspended accounts get 200. It also calls the treatment-12 arrangement flag "settlement eligibility".

**Sonnet.** The modules follow the spec's sections and have docstrings that cite the spec. The long docstrings are essay-like. Three things work against it:
- Every table (matrix, scorecard, bands, recovery curve) and both overlay registers are built in Python, not in `configs/` documents. `params.json` holds only toggles and 02's params. Collections Strategy therefore cannot change the matrix without a release (AC1, and BRIEF "Style").
- `CAPACITY_SUPPLY` and `ranking_basis` are module constants or build arguments (`capacity_alloc.py:237,329`); the tests monkeypatch them. The spec requires the basis to be switchable "without a release".
- `times_cured_24m` and `under_performing_arrangement` are declared `param()` (`state.py:45-47`), so the §4.3 hold/floor rules can never fire from account data. With `times_cured_24m=2, days_past_due=10` the bucket stays 1. Its own NOTES §4.2 documents exactly this pitfall.

**Sonnet summary: 4/5.** It gets the stages, overlays, dual path run and import collision right. It missed that the cure-floor and chronic re-entry outputs are discarded (`path.py:114`), that the path never alters the treatment, and the non-selection codes. It also calls roll probability "probability of default".

## 5. Struggles

**Haiku.** All of these are agent capability problems:
- It misdiagnosed the `-> dict` build failure as a framework param-constraint bug, and reported a workaround that was never applied.
- It declared every input as `param()`.
- It shipped in a nested directory.
- NOTES contradicts the code on tests, sample output, suspension count and overlays, and the build is claimed to work "with workaround".

**Sonnet.**

*Framework problems:*
- The `sys.path` guard in the handler (`decider/serving/handler.py:214-215`, verified) lets a `PYTHONPATH` entry shadow `CODE_PATH`. Every project names its entry point `pipeline.py`, so the wrong project's pipeline can be served silently. Sonnet worked around it with a file-path import of 02.
- A JSON `null` date crashes at the Arrow boundary; the workaround is placeholder dates in the sample.
- `missing_as(False)` is truthy when a step is called directly.
- A chained `.relabel(writes=)` is a silent no-op.
- `dag` versus `flow` for same-name writes is detected late.
- The warm-up synthesiser does not know `date`, which forced the private `_warm` monkeypatch.
- `frame_step` has no params channel.

*Agent capability:*
- The param-for-input bug in `state.py`, despite documenting the pitfall.
- Treating the 14 non-hard suspensions as non-restricting, which leaves 101 and 111 contactable.
- The curl route was never verified.
- Tables were kept in code.

*Spec problems (reasonable):*
- The cure window is 6 months in §4.3 but 12 in §5.5.
- The §13 Q1 sequence-position question is left open.
- The single ranking basis per run is implicit.

Out of scope for both: the ~200k-account × 10-day volume. Sonnet ran on a handful of accounts only; Haiku did not attempt it.
