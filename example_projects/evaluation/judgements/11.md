## 2. Similarity

Both split the slice the same way: EP-1 over "05's whole assessment", L1 as re-assess-and-compare against a prior decision, and a stand-alone DSCR covenant. The resemblance ends there.

**Haiku: three monolithic `@step`s returning dicts.** Request facts are declared as `param()`: `amount`, `ebitda`, `prior_grade` (`pipeline.py:28-30, 82-83, 137-139`).
- The covenant version is a literal `"2026-01"` (`pipeline.py:159`), and `test_date` defaults to `date.today()`.
- Migration is `current - prior` plus one of two codes (`assessment.py:141-153`).
- There is no bi-temporal query, no partial re-assessment and no gap register in code.

**Sonnet: a real composition.** EP-1 is `dag(project05.build(), …11's steps…).emit(...)` (`origination.py:62-84`).
- **Covenant:** a three-version DSCR library, resolved once through 00's `EffectiveDatedSet` and pinned on the instance. It records test, delivery and determination dates separately, and a "not tested" state (`covenant.py`). This matches §5.5.1–5.5.2.
- **Bi-temporal queries:** `query_knowledge` and `query_effective` reproduce §5.13.2's director-resignation example (`test_history.py`). They are plain functions, though, and never feed structure resolution.
- **L1:** `review.annual_review` re-runs 05 three times for counterfactuals and produces all four §5.4.1 outputs. It calls 07 for the limit decision on revolving facilities.
- **Daily pass:** 05's `partial_reassess_entity` is called and shown equal to a full re-run (`test_daily_pass.py`).

**Sonnet's L1 core has real defects:**
- **The review tests review a declined application.** The "clean-enough applicant … so the facility actually originates" fixture (`test_review.py:30`) scores `outcome_code` 4 at grade 11. I checked this by running the fixture. The tests only assert `outcome_code in (1,2,3,4)`.
- **The stale-basis cap is inverted.** `min(current_grade, grade_cap)` (`review.py:224`) turned that grade 11 into **7** on a stale review, which makes a degraded review *upgrade* the client four notches. Grades run worse-upwards: PD 0.34 maps to grade 11, and `vocab.EXIT_GRADE_FLOOR` means "10 or worse". §5.4.3 says degradation restricts. The test asserts `<= 7`, which enshrines the bug.
- **The cause decomposition double-counts overlay.**
  - `pd3 = pd_current` (`history.py:167`), so `entity_data` absorbs model and overlay, and `model` is identically 0.
  - `overlay` is then counted again (`:178`), and `scale` becomes −overlay.
  - With the implementation's own test fixture, I got causes `{…, overlay 0.01, scale −0.01}` and `residual_is_defect: True` on an unchanged master scale. The test does not assert this flag.
  - NOTES claims "model and scale are always zero" and that overlay is "genuine, independently-measured". Both claims are false.

**Verdict:** Sonnet is much closer to the spec.

**Haiku**
- **Agent capability, the main cause:**
  - invented CLI flags and output;
  - `RequestHandler` imported from the wrong module;
  - request data declared as params;
  - `date.today()` in decisions;
  - the only pipeline served is the covenant step;

**Sonnet**

  - Str table selectors force interpreted mode.
  - The input/output shadowing `EngineError` it praises as actionable.
- **Spec:** 06 is "hard" in DEPS but only used by L5, which SCOPE skips. 05 publishes no `master_scale_version` (recovered from the cell id). Model and scale causes are not measurable without multi-version infrastructure. The 1 280 figure is inconsistent, as shown in §4.

- **Process:** the implementer spawned writing forks into a shared directory. They overwrote the deliverable after it was reported, and the report described code that was not shipped.
