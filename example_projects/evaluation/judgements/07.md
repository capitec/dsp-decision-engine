## 2. Similarity

Both implementations reached the same conclusion about the hard part: §5.8 allocation needs the whole population, so it cannot be a per-record `decider` step. Haiku says this in NOTES ("Friction 1", "What I would do next 3"). Only Sonnet built it: a per-account `dag` (`pipeline.py:102-153`) is run in batch with `Engine.run`, and then plain-polars `run_allocation()` runs over the whole frame (`allocation.py:387`).

Haiku puts every stage inside one step. Its "allocation" funds any rankable account whose increase is at most the R3.31 bn envelope (`pipeline.py:124-131`). That is the per-account stand-in for the budget that §5.8 explicitly warns against. The population `allocate_budget()` it does have (`limit_management.py:363`) is never called.

Other design differences:
- **Matrix.** Sonnet uses a 1 152-row `DecisionTableConfig` loaded from `configs/0.1.0/matrix.json` (verified: 1152 rows). Haiku generates a dict at runtime whose multiplier ignores the mob and product dimensions.
- **Overlays.** Sonnet builds them on 00's `core.adjustments` (score shift, PD multiplier, dial on the excess, buffer +6 pp), and the stack can be switched off through params. Verified: the multiplier goes 1.1238 → 1.1547 and the buffer 0.3191 → 0.2591. Haiku has a single `cycle_dial_multiplier` param.
- **Affordability.** Sonnet uses 02's units. Haiku uses an inline `income − obligations − instalment ≥ 0` (`pipeline.py:104-107`).

Spec worked examples where both could run:

| Example | Haiku | Sonnet |
|---|---|---|
| 80% dial: 1.50 → 1.40 | ✓ | ✓ |
| 40.0% utilisation falls in the 40–55% band | ✓ | ✓ |
| C5: R6 000 limit, R400 spend → held at R6 000, C5 binds | ✓ | ✓ |
| R25 000 card → R875 notional instalment | ✓ | ✓ |
| Round down to R500 | ✓ | ✓ |
| No part-funded increases | n/a | ✓ (`funded_amount` = increase, max diff 0.0) |
| Ties broken by `account_id` | ✗ | ✓ |

Both implementations share one bug: **the 0% utilisation band is unreachable**. Utilisation 0 goes to the 0–10% band in both. In Sonnet's `population.py:30` only 7 of the 8 bands can be reached, so matrix `util_band 8` (the "above 90%" penalty) is dead.
